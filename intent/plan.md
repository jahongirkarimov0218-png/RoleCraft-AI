# План реализации: страница `/niche-report`

> Сделан из intent: [`intent/niche-analysis-intent.md`](./niche-analysis-intent.md) (автор: Рома Райт, статус: черновик)
> Требования и архитектура: [`intent/spec.md`](./spec.md) · Ветка: `ccr-9ff4fe73-j2y2dz` · Дата: 2026-10-12
> Статус плана: согласован, реализация не начата.

Цель: одна статическая страница в браузере. На ней вердикт с одной нишей (операционка клиник или маркетинг для МСБ, Узбекистан), 1–3 причины выбора и тест на 14 дней с числовым порогом «идём / вторая ниша».

Принятые по умолчанию решения из spec:
- C-01: страница только локально, флаг `NICHE_REPORT_ENABLED` по умолчанию выключен.
- C-02: группы маршрутов, у отчёта свой layout.

Если C-01 решится в пользу доступа извне, шаг 3 меняется на отдельный HTML вне Next.js.

## 2. Порядок работ

Каждый шаг — отдельный коммит. Следующий шаг начинается только после зелёной проверки предыдущего.

| # | Шаг | Проверка, без которой дальше не идём |
|---|---|---|
| 0 | Точка отсчёта на текущем коде | Сохранить выводы `npm run build`, `npx vitest run` (ожидается 62/62), `npx playwright test`. **Факт (2026-10-12):** build OK, 62/62. E2E на коде до изменений: 18–19 из 20, нестабильно падают `product-flow` «Instant Preview» (Desktop) и `rolecraft` «Scenario 3» (Mobile, проверка мимолётного состояния загрузки). Это пред-существующая нестабильность, в этой задаче не исправляется; критерий для шагов 1+ — новых падений нет. В контейнере Chromium 1194, а `@playwright/test` 1.63 ждёт 1243, поэтому локально запускается через неотслеживаемую обёртку конфига с `executablePath: /opt/pw-browsers/chromium` (в репозиторий не коммитится) |
| 1 | Перенос в `(main)/` | build OK; 62/62; старые E2E зелёные, как в шаге 0; `/nonexistent` → 404 (R1) |
| 2 | `types.ts`, `validate.ts`, `guard.ts`, `test/niche-report.test.ts` | Тесты зелёные, включая кейс «работа с клиниками» без ложного срабатывания V-11 (R3). Если временно убрать V-03 и V-08 из валидатора, их негативные кейсы должны падать |
| 3 | `report-data.ts` (тестовые данные, `draft`), `(report)/layout.tsx`, `page.tsx`, `print-button.tsx` | build OK; с флагом страница открывается, без флага — 404; в `<head>` есть `noindex` |
| 3a | *Уточнения при реализации шага 3* | Тестовые данные (`draft`) не содержат ни одного факта: все оценки помечены `unknown`, вердикт — первый по списку кандидат с явной пометкой «это не вывод», на странице плашка «Черновик». Одинаковые доказательства получают один номер, чтобы список не дублировался. Чтобы уложиться в 1 лист A4, печатная версия уплотнена `print:`-классами прямо на странице; `globals.css` не тронут. В Chromium 1194 тестовые данные печатаются ровно на 1 лист |
| 4 | `e2e/niche-report.spec.ts` + `playwright.config.ts` | Зелёные на Desktop Chrome и Pixel 5 |
| 4a | *Уточнения при реализации шага 4* | Проверка «1 лист A4» сделана точной: тест считает страницы в PDF из `page.pdf()` Chromium, а не прикидывает по высоте. Добавлен сценарий 6: черновик виден как «Это не вердикт». Сценарий «404 без флага» закрыт unit-тестом гарда и ручной проверкой собранного приложения (`next start`) |
| 5 | ADR-0004, `.env.example`, `AGENTS.md` | Счётчики в `AGENTS.md` совпадают с фактическим выводом тестов |

## 3. Риски

| ID | Что может сломаться | Шаг | Как ловим / предотвращаем |
|---|---|---|---|
| R1 | После переноса у `app/` нет общего корневого layout. Неизвестные URL могут отдать ошибку вместо 404 | 1 | Проверка `/nonexistent` → 404. Если сломалось — `src/app/(main)/not-found.tsx` или возврат к странице под текущим layout |
| R2 | `/` теряет стили, шрифт или metadata из-за неверного пути к `globals.css` | 1 | build + старые E2E + визуальная сверка `/` до и после |
| R3 | V-11 ложно срабатывает: «бот» — подстрока «работа». `\b` в JS не работает для кириллицы | 2 | Совпадение только целого слова: `(?<!\p{L})бот(?!\p{L})` с флагом `u` + негативный кейс |
| R4 | E2E падает с 404, потому что переиспользуется уже запущенный dev-сервер без флага (`reuseExistingServer: true`) | 4 | Предупреждение в шапке spec-файла; первый сценарий падает с понятным сообщением |
| R5 | Флаг включён в Vercel → личные данные публичны. `noindex` от этого не защищает | релиз | Флаг читается при сборке, по умолчанию выключен; пункт в чек-листе релиза |
| R6 | V-12 считает слова в данных, а не на отрисованной странице | 2–3 | Лимит с запасом; итог решает ручная печать |
| R7 | Подсчёт листов A4 в Playwright зависит от версии Chromium | 4 | Считаются страницы реального PDF из `page.pdf()`; итог всё равно подтверждается ручной печатью в Chrome |
| R8 | V-03 (строгий максимум) делает отчёт невыпускаемым при ничьей | 7 | Это намеренно: ничья означает, что нужен ответ на блокирующий вопрос, а не правка правила |
| R9 | Выдуманные или устаревшие данные дают уверенный неверный вердикт | 7 | V-08 (источник обязателен), V-09 (≤180 дней), ручная сверка каждой ссылки |

**Самый рискованный шаг:**
- для кода — **шаг 1**: он трогает все существующие страницы. Поэтому идёт первым, отдельным коммитом, с точкой отсчёта до и после;
- для результата intent — **шаг 7**: код проверяет форму, но не правдивость.

## 4. Проверка: как доказывается результат intent

| Требование intent | Доказательство | Тип |
|---|---|---|
| Отчёт на одну страницу в браузере | E2E: 200 на 1440px и 375px, нет горизонтального скролла; печать → 1 лист A4 (E2E-эвристика + ручная печать); V-12 ≤700 слов | Автоматически + вручную |
| Вердикт: одна ниша | V-03: строгий максимум взвешенного балла, ничья — ошибка; E2E: ровно один `[data-testid=verdict]` | Автоматически |
| Причины, почему выбрана она | V-04: 1–3 причины со ссылками на критерии | Автоматически |
| Тест на 14 дней с порогом, иначе вторая ниша | V-06, V-07; E2E: число порога видно на странице | Автоматически |
| «Все ниши интересны» = провал | V-03 + V-04 + порядок блоков «вердикт → тест → матрица» | Автоматически |
| Блокер «нет критериев» снят | V-01: веса в сумме дают 1, у каждого есть `rationale`; V-05: у каждой оценки есть доказательство | Автоматически |
| Только два рынка, без идеи приложения | V-02 (id кандидатов); V-11 (запрещённые слова) + ревью текста | Автоматически + вручную |
| Не додумывать | V-08: у факта есть https-источник; V-09: не старше 180 дней; V-10: если есть `unknown`, блок «неизвестное» не пуст | Автоматически |
| Отчёт не публичен | Unit-тест гарда (404 без флага), `noindex`, флаг выключен в Vercel | Автоматически + вручную |
| Ничего не сломано | build OK; 62 старых + новые unit-тесты; старые E2E зелёные | Автоматически |

«Готово» заявляется только при выполнении всех пунктов DoD из spec §8.3, с приложенными выводами команд.

**Что проверки не доказывают:**
- Правильность самого вердикта и то, что источники говорят именно то, на что ссылается отчёт. Это ручная сверка в шаге 7 и решение Ромы при переводе в `final`.
- Итоговый критерий intent — анализ остановлен и тест запущен. Это видно только по факту.
